# Provider compatibility matrix

This matrix is a design stress test, not an implementation roadmap. Only Cloudflare Web
Analytics, Cloudflare Analytics Engine, and Google Search Console are implemented. The remaining
rows check that shared contracts do not assume one provider's shape.

| Provider                    | Query model                              | Metrics and dimensions                                       | Dynamic schema                                              | Sampling / quality                                                            | Events and browser ownership                                           | Archive suitability                                                                   | Retention                 |
| --------------------------- | ---------------------------------------- | ------------------------------------------------------------ | ----------------------------------------------------------- | ----------------------------------------------------------------------------- | ---------------------------------------------------------------------- | ------------------------------------------------------------------------------------- | ------------------------- |
| Cloudflare Web Analytics    | GraphQL aggregate groups                 | Fixed traffic metrics; time and supported breakdowns         | No                                                          | Dynamic sampling; expose sample interval, approximation, and partial warnings | Cloudflare owns the beacon; no custom events                           | Good for daily aggregate totals with quality metadata                                 | Previous 6 months         |
| Cloudflare Analytics Engine | SQL over a named dataset                 | Current adapter exposes event count, time, and name          | Dataset is dynamic; current adapter is intentionally narrow | Sample interval must remain visible                                           | SDK can write bounded native data points; host owns the binding        | Good for daily event totals within native retention                                   | 3 months                  |
| Google Search Console       | Search Analytics request with pagination | Fixed search metrics; date/hour and search dimensions        | No                                                          | Top-row limits, incomplete data, Pacific calendar boundaries                  | No browser tracker                                                     | High value because native history expires; archive only safe additive/derived metrics | About 16 months           |
| GA4                         | Data API report requests                 | Property-defined custom metrics and dimensions               | Yes                                                         | Thresholding, sampling, quotas, freshness vary by request                     | Google tag or host integration owns sessions, consent, and identity    | Suitable only with explicit compatible materializations                               | Property and plan defined |
| Matomo                      | Reporting HTTP API                       | Core reports plus site-defined dimensions and goals          | Partly                                                      | Can archive reports server-side; quality depends on deployment                | Matomo tracker owns sessions, consent, and identity                    | Suitable when deployment retention and archive processing are known                   | Deployment defined        |
| Plausible                   | Stats API aggregate queries              | Small fixed web metrics with goal/property extensions        | Partly                                                      | Aggregate API limitations must be warnings, not erased                        | Plausible script owns visitor semantics                                | Suitable for supported aggregate intervals                                            | Plan defined              |
| Umami                       | REST analytics queries                   | Web metrics, events, URLs, referrers, devices                | Partly                                                      | Self-hosted data completeness and API limits are deployment facts             | Umami tracker owns sessions and event transport                        | Suitable when the deployment exposes stable aggregate queries                         | Deployment defined        |
| PostHog                     | Insights and HogQL queries               | Product analytics schema and arbitrary event properties      | Yes                                                         | Sampling, query limits, and partial execution are query-specific              | PostHog SDK owns autocapture, identity, consent, batching, and retries | Only explicit stable materializations are safe                                        | Plan/deployment defined   |
| Amplitude                   | Analytics HTTP APIs                      | Event, cohort, funnel, and retention models                  | Yes                                                         | Limits and metric definitions vary by endpoint                                | Amplitude SDK owns identity, sessions, batching, and retries           | Aggregate time series may be materialized; funnels are not additive                   | Plan defined              |
| Mixpanel                    | Query APIs over events and cohorts       | Dynamic event properties and endpoint-specific analyses      | Yes                                                         | Endpoint limits and approximations must be retained                           | Mixpanel SDK owns identity, sessions, batching, and retries            | Only compatible aggregate reports are suitable                                        | Plan defined              |
| Vercel Web Analytics        | Project aggregate analytics              | Fixed web metrics plus supported route/referrer/device views | No                                                          | Platform aggregation and availability remain provider quality facts           | Vercel owns collection when its integration is enabled                 | Suitable only where a stable server API and coverage are available                    | Plan defined              |

## Contract implications

- Dataset descriptors must support fixed and dynamic provider schemas without making every
  provider dynamic.
- A shared query does not imply every metric, filter, grain, or dimension is portable.
- Browser event unification stops at the application event API; provider-native sessions,
  identity, consent, autocapture, retry, and batching are not normalized.
- Archive materializations are adapter-selected and metric-rollup-aware. Funnel, retention,
  unique, percentile, and provider-defined results are not silently added across partitions.
- Quality metadata is part of the report contract, not an adapter implementation detail.

# Guide

Install the package with Bun:

```bash
bun add @liria24/analytics
```

Create one analytics instance with an explicit project name and one or more adapters:

```ts
import { createAnalytics } from '@liria24/analytics'
import { cloudflareWebAnalytics } from '@liria24/analytics/cloudflare'

const analytics = createAnalytics({
    name: 'website',
    adapters: [
        cloudflareWebAnalytics({
            accountId: process.env.CLOUDFLARE_ACCOUNT_ID!,
            apiToken: process.env.CLOUDFLARE_API_TOKEN!,
            siteTag: process.env.CLOUDFLARE_SITE_TAG!,
        }),
    ],
})
```

Keep credentials in server secrets. Never place provider tokens in a browser bundle or public
Nuxt runtime config.

## Nuxt

Nuxt loads its config helpers automatically, so no `defineNuxtConfig` import is needed:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
    modules: ['@liria24/analytics/nuxt'],
    analytics: {
        name: 'website',
        events: {
            pageViewed: {
                properties: { path: 'string' },
            },
        },
        providers: {
            cloudflare: { webAnalytics: 'your-site-tag' },
            searchConsole: 'sc-domain:example.com',
        },
    },
})
```

`useAnalytics` is also auto-imported in application code:

```ts
useAnalytics().track('pageViewed', { path: '/guide' })
```

Keep provider bindings in `server/analytics.config.ts`. This example sends the validated relay
events to an Analytics Engine binding without putting the binding or credentials in client
configuration:

```ts [server/analytics.config.ts]
import { cloudflareAnalyticsEngine } from '@liria24/analytics/cloudflare'
import { defineNuxtAnalyticsConfig } from '@liria24/analytics/nuxt/runtime'

export default defineNuxtAnalyticsConfig({
    async eventHandler(events, event) {
        const binding = event.context.cloudflare?.env?.ANALYTICS
        if (!binding) throw new Error('Analytics Engine binding is missing')
        const sink = cloudflareAnalyticsEngine({ binding }).sink
        if (!sink) throw new Error('Analytics Engine sink is missing')
        await Promise.all(events.map((event) => sink.track(event)))
    },
})
```

The module reads Cloudflare account credentials from server-only
`runtimeConfig.cloudflare.accountId` / `runtimeConfig.cloudflare.apiToken`, falling back to
`CLOUDFLARE_ACCOUNT_ID` / `CLOUDFLARE_API_TOKEN`. For Search Console, provide
`getAccessToken()` in the same server config; token refresh and persistence stay in the host
application.

# Architecture

The dependency direction is deliberately simple:

```text
Integration → Adapter → Core
```

- **Core** owns queries, reports, source selection, rollups, and quality metadata.
- **Adapters** translate provider-native requests and responses.
- **Integrations** connect adapters to runtimes such as Nuxt and Nitro.

Core never imports provider or framework code. Adapters never import Nuxt or Vue code.

## Provider semantics are data

Reports retain their source, query time, timezone, freshness, sampling, approximation,
threshold, partial-result status, and warnings. Derived metrics such as CTR are recalculated
from supporting values instead of being summed across partitions.

## Explicit source selection

A query can name its source. Without one, the core uses a configured domain default or a single
compatible source. Multiple compatible sources are an error, not a silent choice.

## Archive

Archive storage uses versioned JSON partitions through unstorage. Live and archived coverage is
split at query time, with boundary de-duplication and quality metadata preserved. Integrations use
the runtime's native storage rather than introducing a second storage system.

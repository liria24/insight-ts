---
title: Queries and reports
description: The shared vocabulary used to request and return analytics data.
---

An analytics query describes the data you need without exposing a provider request format.

```ts
const report = await analytics.query({
    dimensions: ['date', 'country'],
    filters: {
        dimension: 'country',
        operator: 'in',
        value: ['JP', 'US'],
    },
    grain: 'day',
    metrics: ['clicks', 'impressions', 'ctr'],
    range: { from: '2026-08-01', to: '2026-08-26' },
    source: 'google-search-console',
    timezone: 'Asia/Tokyo',
})
```

The common fields are a vocabulary, not a guarantee that every provider supports every
combination. The selected adapter validates metrics, dimensions, filters, grain, range,
pagination, and provider limits before network I/O.

## Report shapes

Queries return one of three report shapes:

- **Scalar** — a set of metric values for the requested range.
- **Series** — time buckets with metric values and optional dimensions.
- **Table** — dimension rows with metric values.

All shapes include `meta` with the selected source, query time, temporal details, freshness, and
quality.

## Domain helpers

Use domain helpers when you expect a time series:

```ts
await analytics.traffic.series({ metrics: ['visits'], range: '30d' })
await analytics.search.series({ metrics: ['clicks'], range: '30d' })
await analytics.experience.series({ metrics: ['score'], range: '30d' })
```

Use `analytics.query()` when you need explicit dimensions or a non-series report.

## Rollups

Archive and cross-partition rollup depends on metric semantics:

- additive metrics are summed;
- derived ratios are recalculated from supporting metrics;
- non-additive and provider-defined metrics are not silently combined.

This keeps a valid report from becoming a plausible but incorrect total.

---
title: Concepts
description: Providers, capabilities, reports, History, UI Core, and Integrations in Insight.ts.
---

- A **Provider** is a data or operation target such as Cloudflare, Search Console, Sentry, or an
  application-defined system.
- A **capability** is optional. Today Report Sources implement only the operations they support:
  `summary`, `series`, `breakdown`, and `snapshot`.
- An **Integration** connects Insight.ts to a runtime, server framework, application framework, or
  UI framework. It does not redefine Core semantics.

Queries use absolute ISO ranges with `[from, to)` semantics:

```ts
const traffic = insight.reports('cloudflare.webAnalytics')
const report = await traffic.series({
    metrics: ['pageViews', 'visits'],
    grain: 'day',
    range: { from: '2026-08-01T00:00:00.000Z', to: '2026-09-01T00:00:00.000Z' },
})
```

Reports are strict `ScalarReport`, `SeriesReport`, or `TableReport` values. Provider Quality and
History Fidelity are separate metadata. Filters use generic `field`; provider-native query
languages remain provider escape hatches rather than one giant shared AST.

Core is the dependency root. Provider implementations, History, and `insight-ts/ui-core` depend on
Core independently; Integrations depend only on the layers they connect. UI Core turns reports
into framework-neutral models, while Vue UI owns markup and its private renderer. Nitro owns Nitro
Storage/Tasks wiring; Nuxt composes Nitro rather than reimplementing it.

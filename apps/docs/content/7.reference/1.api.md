title: API reference
description: Public Insight.ts entrypoints and their dependency boundaries.
---

| Entrypoint                         | Purpose                                                   |
| ---------------------------------- | --------------------------------------------------------- |
| `insight-ts`                       | `createInsight`, reports, errors, Core types              |
| `insight-ts/provider`              | `defineProvider`                                          |
| `insight-ts/history`               | History Engine and three-method repository contract       |
| `insight-ts/cloudflare`            | Cloudflare Provider implementations                       |
| `insight-ts/google-search-console` | Search Console Provider                                   |
| `insight-ts/browser`               | Browser event client                                      |
| `insight-ts/ui-core`               | Framework/DOM/renderer-independent UI models              |
| `insight-ts/nitro`                 | Nitro Storage repository and optional task bridge         |
| `insight-ts/nuxt`                  | Thin Nuxt composition and server config helper            |
| `insight-ts/vue`                   | Vue browser provide/inject only                           |
| `insight-ts/vue/ui`                | Optional Vue report components, CSS, and private renderer |

The root client is capability-first:

```ts
insight.reports('cloudflare.webAnalytics')
insight.reports('googleSearchConsole.searchAnalytics')
insight.sources()
insight.track('signup', { plan: 'pro' })
```

Only implemented operations appear in the inferred client. Report Source IDs are derived from
Provider ID and source key; there is no separate `sourceId`, product domain, or state API.

`InsightError` identifies shared failures. Provider-native failures extend `ProviderError` and
preserve status, retryability, and native codes where available.

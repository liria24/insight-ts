Use `insight-ts/nitro` when a Nitro application needs bounded History storage backed by the
`insight` mount. It does not depend on H3, so the same integration works with H3, Hono, Elysia, and
Web-standard server entries.

The entrypoint also exposes `createNitroEventRelay()`, a Web-standard request handler used by the
Nuxt module. It validates fixed body and batch limits plus the configured event schema before
calling canonical server `track()`.

## Create the repository

```ts
import { createHistory } from 'insight-ts/history'
import { createNitroHistoryRepository } from 'insight-ts/nitro'

const history = createHistory({
    repository: createNitroHistoryRepository(useStorage('insight')),
    capabilities: ['metrics', 'logs', 'traces'],
})
```

## Configure storage

```ts
export default defineNitroConfig({
    storage: {
        insight: {
            driver: 'cloudflare-r2-binding',
            binding: 'INSIGHT_HISTORY',
        },
    },
    devStorage: {
        insight: {
            driver: 'fs',
            base: '.data/insight',
        },
    },
})
```

## Tasks are opt-in

`configureNitroHistory()` can register `insight:history:sync` only after your Nitro config enables
experimental tasks. The task invokes the same synchronization behavior as `history.sync()`.

::caution
History is not a persistent query-result cache. Configure a durable `insight` storage mount when
History data must survive process restarts.
::

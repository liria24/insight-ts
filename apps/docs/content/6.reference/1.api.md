The package keeps provider and runtime code behind explicit subpath exports.

| Import                                     | Purpose                                             |
| ------------------------------------------ | --------------------------------------------------- |
| `@liria24/analytics`                       | Core configuration, queries, reports, and errors    |
| `@liria24/analytics/browser`               | Typed same-origin browser event client              |
| `@liria24/analytics/cloudflare`            | Cloudflare Web Analytics and Analytics Engine       |
| `@liria24/analytics/google-search-console` | Google Search Console Search Analytics              |
| `@liria24/analytics/provider`              | `defineAnalyticsProvider()` extension point         |
| `@liria24/analytics/nuxt`                  | Nuxt module and build-time integration types        |
| `@liria24/analytics/nuxt/runtime`          | Nitro relay and server-only configuration helpers   |
| `@liria24/analytics/vue`                   | Vue browser-client helpers and report UI primitives |
| `@liria24/analytics/vue/style.css`         | Vue UI baseline and semantic chart styles           |

## Core

```ts
import { AnalyticsError, createAnalytics, defineAnalyticsConfig } from '@liria24/analytics'
```

The core entry exports `AnalyticsProvider`, `AnalyticsSource`, query and report types, event and
application-state schemas, archive options, and report metadata. Internal Adapter contracts are
not part of the normal public API.

The client exposes:

```ts
analytics.query(query)
analytics.sources()
analytics.source(id).summary(query)
analytics.source(id).series(query)
analytics.source(id).breakdown(query)
analytics.domain(name).summary(query)
analytics.traffic.series(query)
analytics.search.series(query)
analytics.experience.series(query)
analytics.state.current(metrics)
analytics.state.series(metric, query)
analytics.track(name, properties)
analytics.maintenance.run()
```

Capabilities that are not configured fail explicitly. The core does not create HTTP routes,
schedulers, storage drivers, or provider credentials.

## Errors

Provider-independent validation uses `AnalyticsError` with a typed error code, including
`CONFIGURATION_MISSING`. Native API failures extend `AnalyticsProviderError`; built-in Providers
also export their specific subclasses.

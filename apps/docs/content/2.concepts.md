Analytics SDK gives different analytics systems one shared vocabulary without pretending their
data is identical. A query describes the result an application needs; a Provider Source decides
whether its native API can produce that result.

## Architecture

The dependency direction is deliberately simple:

```text
Integration → Adapter → Core
```

- **Core** owns queries, reports, source selection, rollups, events, application state, and archive
  semantics.
- **Adapters** remain internal execution primitives that translate provider requests and responses.
- **Providers** expose one or more queryable Sources and an optional event destination.
- **Integrations** resolve host configuration and connect runtime primitives such as H3, Nitro
  Storage, and Nitro Tasks.

Core never imports provider or framework code. Package entries for core, providers, Nuxt, browser,
and Vue stay separate so an application loads only the layers it uses.

## Queries

An analytics query names metrics, optional dimensions and filters, a time range, and the intended
grain:

```ts
const report = await analytics.query({
    dimensions: ['date', 'country'],
    filters: {
        dimension: 'country',
        operator: 'in',
        value: ['JP', 'US'],
    },
    grain: 'day',
    metrics: ['clicks', 'impressions', 'ctr'],
    range: { from: '2026-08-01', to: '2026-08-26' },
    source: 'google-search-console.search-analytics',
    timezone: 'UTC',
})
```

The fields are a common vocabulary, not a promise that every provider supports every combination.
The selected Source validates metrics, dimensions, filters, grain, range, pagination, and native
limits before network I/O.

Use a domain helper for a time series when the domain is already known:

```ts
const range = {
    from: '2026-08-01T00:00:00.000Z',
    to: '2026-08-31T00:00:00.000Z',
}

await analytics.traffic.series({ grain: 'day', metrics: ['visits'], range })
await analytics.search.series({ grain: 'day', metrics: ['clicks'], range })
await analytics.experience.series({ grain: 'day', metrics: ['score'], range })
```

Use `analytics.source(id)` for a fixed Source, `analytics.domain(name)` for custom domains, and
`analytics.query()` as the advanced escape hatch.

## Providers, Sources, and selection

Each Provider exposes Sources with a stable ID, domain, supported metric and dimension maps, and
safe archive materializations. `analytics.sources()` lists the available catalog. The core selects
exactly one Source in this order:

1. the query's explicit `source`;
2. an explicit default for the requested domain;
3. the only compatible configured source.

Multiple compatible sources are an error. Analytics SDK never selects the first configured
provider and never silently merges provider totals.

## Reports

Queries return one of three provider-independent shapes:

- **Scalar** — metric values for the whole range.
- **Series** — time buckets with metric values and optional dimensions.
- **Table** — dimension rows with metric values.

Every report includes `meta.source`, `queriedAt`, temporal information, freshness, and quality.
Sampling, approximation, thresholds, incomplete coverage, imported data, and provider warnings
remain visible instead of being normalized away.

## Rollups, archives, and caches

Metric descriptors define whether a value is additive, derived, non-additive, or provider-defined.
Additive values can be summed across archive partitions. Derived ratios are recalculated from
supporting metrics. Unsafe values are not silently combined.

Archive storage preserves supported historical materializations as versioned JSON. It is not a
query-result cache; applications use their runtime-native cache for request or response caching.

---
title: Delivery and context
description: Keep server validation authoritative while preserving optional trace context.
---

Server Track validates the configured event schema and routes to every event destination in the
selected Scope. Insight.ts creates the event ID, timestamp, and `origin` on the server. With the
OpenTelemetry integration, the caller's active trace and span are captured before Insight opens its
internal tracking span and may be attached as event context.

Core retries a destination once only when it reports a retryable `ProviderError`, reusing the event
ID without resending successful destinations. Delivery remains at least once: destinations should
deduplicate repeated IDs where supported, while a caller-initiated second `track()` call is a new
operation with a new ID. Providers still own their native transport, sessions, identity, consent,
and attribution. Event properties are never copied into instrumentation attributes.

::warning
Treat browser events as untrusted input. A relay must reject unknown names, properties, types and
system fields, plus oversized bodies and batches, before calling server Track.
::

---
title: First query
description: Configure Cloudflare Web Analytics and query canonical Metrics.
---

This example creates one Cloudflare Provider and queries canonical Metrics. Replace the credentials
and range with your application's values.

## Example

```ts
import { createInsight } from 'insight-ts'
import { cloudflare } from 'insight-ts/cloudflare'

const insight = createInsight({
    providers: [cloudflare({ accountId, apiToken, webAnalytics: { siteTag } })],
})
const dashboard = await insight.query((q) => ({
    traffic: q.metrics({
        metrics: ['pageViews', 'visits'],
        time: {
            from: '2026-08-01T00:00:00.000Z',
            grain: 'day',
            to: '2026-08-08T00:00:00.000Z',
        },
        where: { country: { in: ['JP', 'US'] } },
    }),
}))
```

## What happens

::steps

### Configure the Provider

`cloudflare()` registers only adapters enabled by its options. Their canonical Metrics appear in
autocomplete without `as const` or explicit generics.

### Select Metrics

`q.metrics()` creates a descriptor but does not begin I/O. Provider routing remains internal.

### Await the result

After the callback returns, Insight.ts normalizes equivalent queries, deduplicates them, and asks
the Provider to execute compatible requests. The result stays typed from query to data and metadata.
::

## Cancel a request

Pass an `AbortSignal` as execution options, not inside the capability query.

```ts
await insight.query((q) => ({ traffic: q.metrics(query) }), {
    signal: request.signal,
})
```

::caution
One Metric query may route to several adapters. Each canonical Metric has one owner per Scope, and
the planner rejects incompatible cross-adapter dimensions or filters before I/O.
::

---
title: Materialization
description: Preserve exact canonical data in bounded partitions.
---

Canonical adapters may provide an internal History materializer. Metrics preserve aggregation and
ratio inputs; Logs and Traces preserve stable IDs and order. The Engine partitions large event
ranges, drains native pagination inside one partition, and commits it before fetching the next.
History serves a Metric query only when it can reconstruct every requested projection; otherwise the
whole query executes live.

Materializers describe capture and reconstruction only. The Engine owns gap planning, stable
segment identity, coverage, and refreshability, so repositories remain capability-agnostic.

History keeps the canonical representation exact. It does not sample, filter, truncate, or run
custom transformations. A query executes live when stored data cannot reproduce every requested
projection safely.

```ts
defineMetricAdapter({
    history: {
        grain: 'day',
        metrics: ['requests'],
        timezone: 'UTC',
    },
    // ...
})
```

Metric History never presents a coarser capture as finer data. Query and capture bucket timezones
must match, and non-UTC row captures currently require the exact captured grain. UTC additive
Metrics may roll up to a coarser grain; derived ratios are recomputed from their captured inputs.

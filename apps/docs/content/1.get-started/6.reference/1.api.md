Use this page to find the import that owns a capability. Core stays generic; Provider, History,
runtime, browser, and UI imports remain separate.

## Entrypoints

| Entrypoint                         | Public purpose                                                           |
| ---------------------------------- | ------------------------------------------------------------------------ |
| `insight-ts`                       | `createInsight`, `defineProvider`, generic capability types and errors   |
| `insight-ts/metrics`               | `defineMetricAdapter`, Metric projections, filters, ranges, rollup types |
| `insight-ts/logs`                  | `defineLogAdapter`, canonical Log records, filters, and query types      |
| `insight-ts/traces`                | `defineTraceAdapter`, canonical Trace/Span models and query types        |
| `insight-ts/history`               | `createHistory`, History controller, bounded repository and policy types |
| `insight-ts/cloudflare`            | Cloudflare Web Analytics, Analytics Engine, and Cloudflare errors/types  |
| `insight-ts/google-search-console` | `googleSearchConsole` and Search Console errors/types                    |
| `insight-ts/opentelemetry`         | `createOpenTelemetryInstrumentation`                                     |
| `insight-ts/browser`               | `createBrowserInsight` and browser event types                           |
| `insight-ts/nitro`                 | `createNitroHistoryRepository`, `configureNitroHistory`                  |
| `insight-ts/nuxt`                  | Nuxt module and `defineNuxtInsightConfig`                                |
| `insight-ts/ui-core`               | framework- and renderer-independent Metric models and formatters         |
| `insight-ts/vue`                   | `provideBrowserInsight`, `useBrowserInsight`                             |
| `insight-ts/vue/ui`                | Vue Metric components, props, `ui` types, and base CSS side effect       |

## Core client

```ts
const insight = createInsight({ providers, events, history, instrumentation })

const [traffic, errors, failures] = await Promise.all([
    insight.metrics(trafficQuery),
    insight.logs(logQuery),
    insight.traces(traceQuery),
])

await insight.track('signup', { plan: 'pro' })
```

Each configured capability is a direct method and accepts its query plus optional `{ signal }`.
`track()` requires a configured event schema and at least one Provider event destination in the
Scope. Multi-Scope clients select one logical boundary with `insight.scope(name)` before calling a
capability or `track()`.

Metric queries accept `projection: 'aggregate' | 'rows' | 'both'`. Explicit projections return only
the selected, statically inferred fields. Scalar queries default to `aggregate`; dimensions or a time
grain default to `both`.

Paginated results expose only `meta.pagination.next`. Pass that opaque cursor to the same canonical
query; terminal results omit `meta.pagination`.

## Vue UI components

| Component               | Data it renders                                     |
| ----------------------- | --------------------------------------------------- |
| `InsightStat`           | one selected Metric value                           |
| `InsightLineChart`      | all selected time-series Metrics                    |
| `InsightAreaChart`      | all selected time-series Metrics as unstacked areas |
| `InsightBreakdownTable` | selected dimensions and Metrics                     |
| `InsightBarChart`       | one Metric by one dimension                         |
| `InsightSparkline`      | one compact Metric trend                            |
| `InsightQualityNotice`  | cross-cutting `QueryQuality` only                   |

::note
`insight-ts/vue` is not the UI entrypoint. It only provides Vue injection for a Browser Insight
client created by `insight-ts/browser`; components and CSS live in `insight-ts/vue/ui`.
::

## Error and instrumentation boundaries

`InsightError` identifies shared execution failures. Provider-native errors extend `ProviderError`
with status, retryability, and native codes. The optional OpenTelemetry adapter instruments query,
Provider execution, event tracking, and History operations with safe `insight.*` attributes; hosts
own SDKs, exporters, Collectors, and baggage.

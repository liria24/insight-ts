title: Query
description: Query canonical capabilities within one logical Scope.

The consumer model is **Scope → Query / Track / History**. Metrics, Logs, and Traces are canonical
capabilities used by those workflows.

- A **Scope** is a logical analysis boundary such as production, staging, or one customer.
- A **capability contract** owns canonical normalization, adapter planning, deterministic merging,
  result typing, and optional History materialization.
- A **Provider** supplies internal adapters and may deliver application events.
- **Core** resolves the Scope, bounds adapter execution, propagates aborts, and
  creates serializable results.

## Single and multiple Scopes

Use `providers` for the normal single-Scope case:

```ts
const insight = createInsight({ providers })
const overview = await insight.metrics({
    metrics: ['requests', 'errors'],
    time,
})
```

Name Scopes only when the application has real logical boundaries:

```ts
const insight = createInsight({
    scopes: { production: productionProviders, staging: stagingProviders },
})

await insight.scope('production').metrics({ metrics: ['requests'], time })
```

Capability methods do not change between Scopes.

## Results preserve quality

Every result exposes its canonical data directly with `meta.queriedAt` and optional aggregate
`meta.quality`. Metrics return `aggregate` and optional `rows`; Logs and Traces return their arrays
directly.

One Metric query may select fields owned by several adapters. A canonical Metric has one owner per
Scope; dimensions and filters must be supported by every contributing adapter. Incompatible
queries fail before network I/O.

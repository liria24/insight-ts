---
title: Logs
description: Query a stable, typed Log model across observability Providers.
---

Configure one or more Log adapters in a Scope, then query them through `q.logs`. Insight.ts
normalizes timestamps, merges records in newest-first order, and removes duplicates by stable Log
ID. Structured bodies and Provider-mapped attributes are preserved.

```ts
import { defineLogAdapter } from 'insight-ts/logs'

const application = defineLogAdapter({
    filters: ['severity', 'service'],
    attributes: ['tenant'],
    execute: async (query) => fetchApplicationLogs(query),
})

const { errors } = await insight.query((q) => ({
    errors: q.logs({
        limit: 50,
        time: { from, to },
        where: {
            severity: { in: ['error', 'fatal'] },
            service: 'api',
            attributes: { tenant: 'acme' },
        },
    }),
}))
```

Portable fields are `severity`, `service`, `environment`, `traceId`, and `spanId`. The typed
`attributes` record is the escape hatch for Provider-specific fields. A filter must be supported by
every contributing adapter; incompatible filters fail before Provider I/O.

Every record has a stable `id` and `timestamp`. Optional mapped fields include observed time,
severity text, service, environment, trace/span IDs, attributes, and an unmodified structured
`body`. Quality remains attached to each contribution and is also summarized on the result.

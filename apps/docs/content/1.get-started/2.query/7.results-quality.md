---
title: Results and quality
description: Read canonical data, Quality, pagination, and capability metadata correctly.
---

Every capability returns plain serializable canonical data with a shared metadata field.

```ts
type QueryResult<TData extends object, TMeta extends object = {}> = Omit<TData, 'meta'> & {
    meta: TMeta & {
        pagination?: { next?: InsightCursor }
        quality?: QueryQuality
        queriedAt: string
    }
}
```

## Metric results

Metric queries select `aggregate`, `rows`, or `both`, and explicit projections narrow the inferred
result type. Each row shares its `time` and `dimensions` across selected Metric values under
`row.values`. `aggregate` is independent Provider query output, not a reduction inferred from
grouped or limited rows. Definitions carry semantic units, structured aggregation, and rollup; UI
code owns presentation formatting. When one query uses several native responses, `meta.quality`
conservatively describes all selected projections.

## Read metadata at its level

- `meta.quality` is the conservative aggregate for approximation, partiality, sampling,
  thresholding, and warnings.
- `meta.pagination.next` is an opaque continuation for only that result.
- Capability metadata such as Metric freshness and bucket timezone remains separate from Quality.

::tip
Render quality close to the value it qualifies. Do not turn a sampling warning into a zero, a
missing value, or an apparently exact aggregate.
::

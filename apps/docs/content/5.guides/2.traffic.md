title: Traffic analytics
description: Query visits and page views without losing provider-specific quality metadata.

The `traffic` domain covers aggregate navigation and audience activity. The current built-in
traffic dataset is Cloudflare Web Analytics.

## Current data model

| Type       | Names                                                                   |
| ---------- | ----------------------------------------------------------------------- |
| Metrics    | `pageViews`, `visits`                                                   |
| Dimensions | `time`, `browser`, `country`, `device`, `host`, `os`, `path`, `referer` |

The provider supports scalar totals, time series, and breakdown tables when the requested
dimension and grain combination can be translated to Cloudflare GraphQL.

## Time series

Use the domain helper when you need one time dimension:

```ts
const report = await analytics.traffic.series({
    grain: 'day',
    metrics: ['pageViews', 'visits'],
    range: '30d',
})
```

Use `analytics.query()` for explicit sources or additional breakdown dimensions:

```ts
const report = await analytics.query({
    dimensions: ['country'],
    metrics: ['pageViews', 'visits'],
    range: '7d',
    source: 'cloudflare.web-analytics',
})
```

## Interpretation

`pageViews` and `visits` are provider-defined aggregate counts, not SDK-owned session tracking.
Cloudflare owns beacon collection and visitor semantics. The adapter retains sampling interval,
approximation, partial responses, and warnings in `report.meta.quality`.

Both metrics are additive and the built-in daily `time` materialization can be archived. See the
[Cloudflare provider](/providers/cloudflare) for native capability details and [Archive](/guides/archive)
for historical storage behavior.

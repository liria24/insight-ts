title: Archive
description: Preserve supported provider history in runtime-native storage.
---

Analytics archives are versioned monthly JSON materializations in
[unstorage](https://unstorage.unjs.io). They preserve provider history; they are not a general
query-result cache.

Pass an unstorage-compatible `Storage` instance to the core API:

```ts
const analytics = createAnalytics({
    name: 'website',
    adapters: [adapter],
    archive: {
        storage: archiveStorage,
        retention: '2y',
    },
})
```

The application chooses and configures the driver. Use persistent storage in production.

## Maintenance

Run maintenance from your scheduler:

```ts
const result = await analytics.maintenance.run()
```

The operation is designed to tolerate delay, duplication, and concurrent wake-ups. Initial
maintenance uses each provider's internal lookback recommendation. Later runs refresh incomplete
coverage and partitions still inside the provider's finalization window.

A partition is sealed only after:

```text
coverage is complete
and partition end + provider finalization delay is before now
```

Sealed partitions are not fetched again. Retention uses observation timestamps, deletes fully
expired partitions, and safely rewrites supported partial boundary partitions.

## Query behavior

Queries split live and archived coverage without overlap. Additive values are summed, derived
ratios are recalculated from supporting metrics, and unsafe non-additive results remain live
provider queries. Report quality metadata survives the merge.

For Nuxt storage rules and R2 bindings, see the [Nuxt integration](/integrations/nuxt).

title: Archive
description: Preserve supported provider history and application-state observations.
---

Analytics archives are versioned monthly JSON materializations in
[unstorage](https://unstorage.unjs.io). They preserve provider history and Application State
observations; they are not a general query-result cache.

Pass an unstorage-compatible `Storage` instance to the core API:

```ts
const analytics = createAnalytics({
    name: 'website',
    adapters: [adapter],
    archive: {
        storage: archiveStorage,
        retention: '2y',
    },
})
```

The application chooses and configures the driver. Use persistent storage in production.

## What can be archived

Adapters declare concrete materializations rather than archiving arbitrary queries. Current
built-in materializations include daily Cloudflare traffic, daily Analytics Engine event counts,
and daily Search Console clicks, impressions, and CTR. Application State observations are stored
when maintenance runs.

Additive values are summed across partitions. Derived ratios are recalculated from supporting
metrics. Unsafe non-additive values and dimensions absent from a materialization remain live-only.

## Maintenance

```ts
const result = await analytics.maintenance.run()
```

Maintenance tolerates delay, duplication, and concurrent wake-ups. Initial maintenance uses each
provider's internal lookback recommendation. Later runs refresh incomplete coverage and partitions
inside the provider's finalization window.

A partition is sealed only after coverage is complete and the provider finalization delay has
passed. Retention uses observation timestamps, deletes fully expired partitions, and safely
rewrites supported partial boundary partitions.

## Query behavior

Queries split live and archived coverage without overlap. Report source, timezones, freshness,
sampling, approximation, and warnings survive the merge.

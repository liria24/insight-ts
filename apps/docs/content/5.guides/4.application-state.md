---
title: Application state
description: Collect current host-owned metrics and retain periodic observations.
---

Application State represents measurements the host application can compute directly: active
subscriptions, seats by plan, queue depth, content counts, or another point-in-time business
state. It does not require a Provider.

## Define metrics and a collector

```ts
const config = defineAnalyticsConfig({
    name: 'application',
    providers: [],
    state: {
        metrics: {
            activeSubscriptions: {},
            seats: {
                dimensions: { plan: ['free', 'pro'] },
            },
        },
        async collect({ requested }) {
            return readRequestedBusinessMetrics(requested)
        },
    },
})
```

Metric and dimension names are fixed by the configuration. The collector receives only the
requested names, and its values are validated before they are returned or archived.

## Current values

```ts
const current = await analytics.state.current(['activeSubscriptions', 'seats'])
```

`current()` invokes the host collector. It is not a provider query and it is not read from a
cache.

## Historical series

Application State history requires an archive. Each maintenance run observes configured state
metrics and stores normalized values; `state.series()` reads those observations:

```ts
const report = await analytics.state.series('activeSubscriptions', {
    grain: 'day',
    range: {
        from: '2026-06-01T00:00:00.000Z',
        to: '2026-08-30T00:00:00.000Z',
    },
})
```

Schedulers only wake maintenance. The collector and archive remain the source of truth for what
was observed and when. In Nuxt, define the collector in server-only
`server/analytics.config.ts`.

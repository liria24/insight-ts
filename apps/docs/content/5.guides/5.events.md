---
title: Events
description: Define typed application events and query provider-backed event counts.
---

Analytics SDK unifies event names and property schemas. It does not unify sessions, identity,
consent, autocapture, attribution, batching, retry semantics, or provider-native browser trackers.

## Define a schema

```ts
import { defineAnalyticsConfig } from '@liria24/analytics'

const config = defineAnalyticsConfig({
    events: {
        signupCompleted: {
            properties: {
                plan: ['free', 'pro'],
                invited: 'boolean',
            },
        },
    },
})
```

Server-side `analytics.track()` validates the event and sends it through configured event sinks.
The server creates the event ID, timestamp, and origin.

## Product data and event transport

Event writes and event reports are separate interfaces. An event sink accepts validated writes.
A provider read adapter may expose an aggregate `product` dataset. Cloudflare Analytics Engine,
for example, currently exposes the `events` count with `time` or `name` dimensions; it does not
turn arbitrary event properties into a portable query schema.

Writes are not retried by Analytics SDK because replaying a non-idempotent event could duplicate
data. Read queries can use the provider adapter's bounded transient retry policy.

## Browser relay

The browser client sends bounded batches to a same-origin endpoint:

```ts
import { createBrowserAnalytics } from '@liria24/analytics/browser'

interface Events {
    signupCompleted: { plan: 'free' | 'pro'; invited: boolean }
}

const analytics = createBrowserAnalytics<Events>()
analytics.track('signupCompleted', { plan: 'pro', invited: false })
await analytics.flush()
```

Your server must implement the relay unless an integration provides it. The relay rejects unknown
events, properties, types, extra system fields, oversized bodies, and oversized batches.

Browser telemetry is best effort and must not be treated as authoritative business state. For
Nuxt, `events` defines schema and typing while `relay` explicitly enables the browser runtime and
route.

title: Data model
description: Understand Providers, Sources, domains, metrics, dimensions, reports, and metadata.
---

Analytics SDK organizes data from broad meaning to concrete provider capability:

```text
Provider → Source → Domain → Metric / Dimension → Query → Report
```

A **Provider** groups one service integration. A **Source** is one queryable interface whose
descriptor declares its domain, metric and dimension maps, and archive materializations.

## Domains

| Domain       | Represents                                          | Current interface                                                              |
| ------------ | --------------------------------------------------- | ------------------------------------------------------------------------------ |
| `traffic`    | Visits and page navigation                          | `analytics.traffic.series()` or `analytics.query()`                            |
| `search`     | Organic search visibility and acquisition           | `analytics.search.series()` or `analytics.query()`                             |
| `product`    | Application events and product usage                | `analytics.track()` for writes; summary, series, or breakdown for read Sources |
| `experience` | Performance or experience measurements              | `analytics.experience.series()` when a compatible Source is configured         |
| `state`      | Host-defined point-in-time application measurements | `analytics.state.current()` and `analytics.state.series()`                     |

Domains do not force Providers into one schema. Cloudflare Web Analytics and a future traffic
provider can both use `traffic` while exposing different dimensions or quality constraints.

## Metrics

A metric descriptor records more than a name. It includes a value type, native aggregation, and
rollup behavior:

- **additive** values such as page views, visits, clicks, impressions, and event counts can be
  summed across compatible partitions;
- **derived** values such as CTR are recomputed from their numerator and denominator;
- **non-additive** values such as average position are not summed;
- **provider-defined** values remain subject to their native semantics.

`null` means the provider did not produce a usable numeric value. It is not silently converted to
zero.

## Dimensions and time

Dimensions describe how metrics are grouped: for example `time`, `country`, `path`, `query`, or
`device`. Provider Sources validate the requested combination before I/O.

Time is represented by a half-open range (`from` inclusive, `to` exclusive), a grain, and timezone
metadata. Providers may use a fixed source calendar. Reports preserve both the source timezone and
the bucket timezone so presentation code does not have to infer them.

## Report shapes

The requested dimensions determine the useful report shape:

- `scalar` contains one metric-value object for the range;
- `series` contains ordered time points;
- `table` contains dimension rows and metrics.

All three include the same metadata envelope. Check `report.meta.quality` and
`report.meta.freshness` before presenting sampled, partial, approximate, or incomplete data as an
exact result.

## Sources

Source IDs are stable references such as `cloudflare.web-analytics` and
`google-search-console.search-analytics`. Source resolution prefers `analytics.source(id)`,
then a domain default, then a single compatible Source. Ambiguity is an error rather than an
implicit merge.

---
title: Traces
description: Search traces and load correlated span detail through one stable result shape.
---

Canonical Traces use common OpenTelemetry semantics without requiring Provider-native field paths.
Search and trace-by-ID share one result shape: filter `traceId` when you need detail, and inspect the
optional `spans` array when the backend returned complete span data.

```ts
const failures = await insight.traces({
    limit: 32,
    time: { from, to },
    where: {
        status: 'error',
        service: 'api',
        durationMs: { gte: 250 },
    },
})
```

Portable filters cover trace ID, root/span name, service, environment, status, and duration.
`attributes` carries Provider-specific filters when the configured Providers support the key.
Incompatible filters fail before Provider I/O.

Each Trace has a stable `traceId` and start time. Optional fields include end time, duration, root
span, service, environment, status, span count, and attributes. Detailed spans preserve canonical
trace ID, span ID, parent span ID, name, timing, kind, status, service, and attributes so Logs can
correlate through the same trace/span identifiers.

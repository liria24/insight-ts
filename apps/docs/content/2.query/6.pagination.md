---
title: Pagination
description: Continue one canonical result without rebuilding its query.
---

Pagination belongs to one QueryResult. Callers do not rebuild the original query or manage a
Provider cursor.

```ts
const first = await insight.logs({ time, limit: 50 })
const second = first.meta.pagination ? await insight.next(first) : undefined
```

You do not repeat the time, filters, limit, or other inputs. QueryResult stays plain serializable
data and never contains an executable `next()` method.

Continuation also works after normal serialization:

```ts
const restored = JSON.parse(JSON.stringify(first))
const second = await insight.next(restored)
```

## Opaque continuation

`meta.pagination.next` is opaque continuation state. Do not parse, modify, or replace it. At the
terminal page, `meta.pagination` is omitted and `insight.next(result)` fails with `INVALID_QUERY`.

Use the same scoped client that produced a result:

```ts
const production = insight.scope('production')
const first = await production.logs({ time, limit: 32 })
const second = await production.next(first)
```

The same result-oriented API continues live and History-backed results. Provider and storage cursor
formats remain private.

---
title: Query
description: Query canonical capabilities within one logical Scope.
---

Query, Track, and History are the three primary workflows. Query reads canonical Metrics, Logs,
and Traces through direct methods such as `insight.metrics()`. The default client uses one implicit
Scope, so most applications do not need to name one.

Providers determine which canonical fields and operations are available. Consumer queries use the
same capability methods regardless of the configured Provider.

## Single and multiple Scopes

Use `providers` for the normal single-Scope case:

```ts
const insight = createInsight({ providers })
const overview = await insight.metrics({
    metrics: ['requests', 'errors'],
    time,
})
```

Name Scopes only when the application has real logical boundaries:

```ts
const insight = createInsight({
    scopes: { production: productionProviders, staging: stagingProviders },
})

await insight.scope('production').metrics({ metrics: ['requests'], time })
```

Capability methods do not change between Scopes.

Use ordinary `Promise.all()` for concurrent queries. Calls keep independent results, errors, and
cancellation. Compatible concurrent queries may share native work internally when it is safe and
supported by the configured Provider.

```ts
const [traffic, errors] = await Promise.all([
    insight.metrics({ metrics: ['visits'], time }),
    insight.logs({ time, limit: 50 }),
])
```

## Results preserve quality

Every result exposes its canonical data directly with `meta.queriedAt` and optional aggregate
`meta.quality`. Metrics return `aggregate` and optional `rows`; Logs and Traces return their arrays
directly.

Configured Metrics determine which dimensions and filters can be selected together. Incompatible
queries fail before network I/O.

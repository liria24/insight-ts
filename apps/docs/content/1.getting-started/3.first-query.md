---
title: First query
description: Configure Cloudflare Web Analytics and select a typed Source.
---

This example creates one Cloudflare Provider and queries its `webAnalytics` Source. Replace the
credentials and range with your application's values.

## Example

```ts
import { createInsight } from 'insight-ts'
import { cloudflare } from 'insight-ts/cloudflare'

const insight = createInsight({
    providers: [cloudflare({ accountId, apiToken, webAnalytics: { siteTag } })],
})
const dashboard = await insight.query((q) => ({
    traffic: q.source.cloudflare.webAnalytics({
        metrics: ['pageViews', 'visits'],
        time: {
            from: '2026-08-01T00:00:00.000Z',
            grain: 'day',
            to: '2026-08-08T00:00:00.000Z',
        },
        where: { country: { in: ['JP', 'US'] } },
    }),
}))
```

## What happens

::steps

### Configure the Provider

`cloudflare()` returns the canonical built-in Provider and exposes only Sources enabled by its
options. No `as const` or explicit generic is required.

### Select the Source

`q.source.cloudflare.webAnalytics()` creates a descriptor but does not begin I/O. The canonical
Source ID remains `cloudflare.webAnalytics` in metadata and execution.

### Await the result

After the callback returns, Insight.ts normalizes equivalent queries, deduplicates them, and asks
the Provider to execute compatible requests. The result stays typed from query to data and metadata.
::

## Cancel a request

Pass an `AbortSignal` as execution options, not inside the Source query.

```ts
await insight.query((q) => ({ traffic: q.source.cloudflare.webAnalytics(query) }), {
    signal: request.signal,
})
```

::caution
Queries from different Sources are not merged. Combine them in application code only when their
units, ranges, and semantics make that combination meaningful.
::

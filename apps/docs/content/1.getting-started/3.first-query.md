---
title: First query
description: Configure a provider adapter and request a typed analytics report.
---

Create one analytics instance with an explicit project name and one or more adapters:

```ts
import { createAnalytics } from '@liria24/analytics'
import { cloudflareWebAnalytics } from '@liria24/analytics/cloudflare'

const analytics = createAnalytics({
    name: 'website',
    adapters: [
        cloudflareWebAnalytics({
            accountId: process.env.CLOUDFLARE_ACCOUNT_ID!,
            apiToken: process.env.CLOUDFLARE_API_TOKEN!,
            siteTag: process.env.CLOUDFLARE_SITE_TAG!,
        }),
    ],
})
```

Query a daily traffic series:

```ts
const report = await analytics.traffic.series({
    grain: 'day',
    metrics: ['pageViews', 'visits'],
    range: '30d',
})
```

The result is a provider-independent series report:

```ts
report.kind
report.points
report.meta.source
report.meta.quality
report.meta.freshness
```

The adapter preserves provider facts such as sampling and incomplete coverage in
`report.meta`. Your application can render, cache, or store the report without depending on a
provider-native response shape.

## Multiple providers

Give each configured dataset a unique source ID. When more than one compatible source exists,
select one in the query or configure a domain default:

```ts
const report = await analytics.query({
    source: 'cloudflare-web-analytics',
    metrics: ['pageViews'],
    range: '7d',
})
```

Analytics SDK never chooses the first configured provider and never silently merges totals from
different providers.

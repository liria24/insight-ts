Use `insight-ts/nitro` when a Nitro application needs the three-method History repository backed by
the `insight` storage mount. It does not depend on H3, so the same integration works with H3, Hono,
Elysia, and Web-standard server entries.

## Create the repository

```ts
import { createHistory } from 'insight-ts/history'
import { createNitroHistoryRepository } from 'insight-ts/nitro'

const history = createHistory({
    repository: createNitroHistoryRepository(useStorage('insight')),
    sources: ['cloudflare.webAnalytics'],
})
```

## Configure storage

```ts
export default defineNitroConfig({
    storage: {
        insight: { driver: 'cloudflare-r2-binding', binding: 'INSIGHT_HISTORY' },
    },
    devStorage: {
        insight: { driver: 'fs', base: '.data/insight' },
    },
})
```

## Tasks are opt-in

`configureNitroHistory()` can register `insight:history:sync` only after your Nitro config enables
experimental tasks. The task wakes `sync()`; range planning, Provider fetches, safe rollup,
reduction, Fidelity, and idempotency stay in the History Engine.

::caution
History is not a persistent query-result cache. It stores Source-declared Metric materializations;
filtered or unsupported History queries continue to execute live.
::

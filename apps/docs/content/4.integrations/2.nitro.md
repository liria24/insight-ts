---
title: Nitro
description: Connect Insight History to Nitro Storage and optionally Nitro Tasks.
---

`insight-ts/nitro` owns the runtime bridge. It uses the well-known `insight` mount and does not
depend on H3, so the same repository works with H3, Hono, Elysia, or a Web-standard server entry.

```ts
import { createNitroHistoryRepository } from 'insight-ts/nitro'

const repository = createNitroHistoryRepository(useStorage('insight'))
```

Configure storage with native Nitro options:

```ts [nitro.config.ts]
export default defineNitroConfig({
    storage: {
        insight: { driver: 'cloudflare-r2-binding', binding: 'INSIGHT_HISTORY' },
    },
    devStorage: {
        insight: { driver: 'fs', base: '.data/insight' },
    },
})
```

History fails explicitly when neither mount exists. Tasks named `insight:history:sync` and
`insight:history:capture` are registered only when both History Tasks and Nitro's experimental
Tasks support are explicitly enabled.

---
title: Nuxt
description: Compose Insight.ts with Nitro without coupling providers, History, or UI.
---

Add the module and enable built-in Providers in `nuxt.config.ts`. Credentials stay in private
top-level Provider runtime config, so production values can be supplied by `NUXT_CLOUDFLARE_*`
environment variables without being embedded into the build. Every built-in Provider uses its
own `runtimeConfig.<provider>` key rather than nesting credentials below `runtimeConfig.insight`:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
    modules: ['insight-ts/nuxt'],

    insight: {
        providers: {
            cloudflare: { webAnalytics: true },
        },
    },

    runtimeConfig: {
        cloudflare: {
            accountId: '',
            apiToken: '',
            host: 'example.com',
            siteTag: '',
        },
    },
})
```

The module auto-imports server-side `useInsight()`:

```ts [server/api/traffic.get.ts]
export default defineEventHandler(() =>
    useInsight()
        .reports('cloudflare.webAnalytics')
        .series({
            grain: 'day',
            metrics: ['pageViews', 'visits'],
            range: { from: '2026-08-01T00:00:00.000Z', to: '2026-09-01T00:00:00.000Z' },
        }),
)
```

`useInsight()` is a server accessor. The Vue browser integration deliberately uses
`useBrowserInsight()` so browser tracking and server report access cannot be confused.
Its configured source, metric, and operation names remain typed; it is not an `any` accessor.

## History through Nitro Storage

Nuxt composes `insight-ts/nitro`; it does not implement a second repository or task system.

```ts [nuxt.config.ts]
export default defineNuxtConfig({
    modules: ['insight-ts/nuxt'],
    insight: { history: { sources: ['cloudflare.webAnalytics', 'app.usage'] } },
    nitro: {
        storage: {
            insight: {
                driver: 'cloudflare-r2-binding',
                binding: 'INSIGHT_HISTORY',
            },
        },
        devStorage: {
            insight: {
                driver: 'fs',
                base: '.data/insight',
            },
        },
    },
})
```

History fails explicitly when neither `nitro.storage.insight` nor
`nitro.devStorage.insight` exists. Nitro Tasks are experimental and remain opt-in: set
`history.tasks: true` and enable Nitro Tasks yourself to register
`insight:history:sync` and `insight:history:capture`.

The module never scans UI source, injects UI CSS, enables Vapor, or imports Vue UI/TanStack
Charts. Import `insight-ts/vue/ui` in application code only when those components are needed.

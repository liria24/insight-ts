---
title: Nuxt
description: Compose Insight.ts with Nitro without coupling Providers, History, or UI.
---

Enable built-in Providers in `nuxt.config.ts`; keep credentials in private top-level runtime config:

```ts
export default defineNuxtConfig({
    modules: ['insight-ts/nuxt'],
    insight: { providers: { cloudflare: { webAnalytics: true } } },
    runtimeConfig: {
        cloudflare: { accountId: '', apiToken: '', host: 'example.com', siteTag: '' },
    },
})
```

`useInsight()` is server-only and typed from the configuration:

```ts
export default defineEventHandler((event) =>
    useInsight().query(
        (q) => ({
            traffic: q.source('cloudflare.webAnalytics', {
                metrics: ['pageViews', 'visits'],
                time: { ...range, grain: 'day' },
            }),
        }),
        { signal: event.request.signal },
    ),
)
```

Nuxt composes the Nitro History repository. Configure `nitro.storage.insight` or
`nitro.devStorage.insight`; missing mounts fail explicitly. The optional
`insight:history:sync` task is registered only when both Insight History tasks and Nitro's
experimental task support are explicitly enabled.

The module does not scan UI source, inject CSS, enable Vapor, import Vue UI, or serialize secrets.

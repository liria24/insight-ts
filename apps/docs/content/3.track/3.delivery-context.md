---
title: Delivery and context
description: Keep server validation authoritative while preserving optional trace context.
---

Server Track validates the configured event schema and uses the selected Scope for routing.
Insight.ts creates the event ID, timestamp, and `origin` on the server. With the OpenTelemetry
integration, the caller's active trace and span may be attached as event context.

A retryable delivery may be attempted once with the same event ID. Delivery remains at least once,
so receiving systems should deduplicate repeated IDs where supported. A caller-initiated second
`track()` call is a new operation with a new ID. Providers still own transport, sessions, identity,
consent, and attribution. Event properties are never copied into instrumentation attributes.

::warning
Treat browser events as untrusted input. A relay must reject unknown names, properties, types and
system fields, plus oversized bodies and batches, before calling server Track.
::

---
title: Browser tracking
description: Batch browser events through a bounded same-origin relay queue.
---

`createBrowserInsight()` queues typed browser events and resolves its same-origin endpoint once.
It flushes after a short interval or immediately when the count or serialized-byte limit is met.

```ts
const browser = createBrowserInsight<{ signup: { plan: string } }>({
    flushIntervalMs: 50,
    maxBatchSize: 20,
    maxBatchBytes: 64 * 1024,
    maxQueueSize: 1000,
    maxRetries: 2,
    onError(error, { dropped, reason }) {
        reportDeliveryFailure(error, { dropped, reason })
    },
})
```

Delivery keeps enqueue order, retries transient network, 408, 429, and 5xx failures with bounded
backoff, and uses `keepalive` for the final `pagehide` flush. Oversized events, queue overflow, and
exhausted batches are dropped through `onError`; explicit `flush()` rejects after a delivery drop.

The Nuxt module registers the default `/api/_insight/events` endpoint. It accepts JSON bodies up to
64 KiB and 100 events, rejects client-supplied IDs, timestamps, origins, and unknown fields, validates
the complete batch against the server event schema, then calls server `track()` for each event. With
named Scopes, set `insight.browser.scope` in `nuxt.config.ts`.

Outside Nuxt, provide `endpoint` and implement the same bounded checks before calling server
`track()`. Browser delivery can repeat after an uncertain response, so use events as telemetry rather
than authoritative state.

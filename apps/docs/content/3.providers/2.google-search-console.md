# Google Search Console

The Search Analytics API cannot use an API key alone. It reads private property data and requires
an OAuth 2.0 access token with the `webmasters.readonly` or `webmasters` scope.

You need:

- **Property** — for example `sc-domain:example.com` or `https://example.com/`.
- **Access-token provider** — a server-only callback returning a current OAuth access token.
- **Google Cloud OAuth client** — needed by the host if it refreshes access tokens.
- **Refresh token** — normally stored in a platform secret for scheduled, unattended queries.

```ts
import { googleSearchConsole } from '@liria24/analytics/google-search-console'

const adapter = googleSearchConsole({
    property: 'sc-domain:example.com',
    auth: {
        getAccessToken: () => getGoogleAccessTokenFromServerSecrets(),
    },
})
```

The SDK does not store credentials, create OAuth callback routes, or require a database. A
single-site application can keep the client secret and refresh token in Cloudflare Worker secrets
or the host platform's equivalent.

With Nuxt, put only the property identifier in `nuxt.config.ts` and supply the host-owned token
callback from `server/analytics.config.ts`:

```ts [server/analytics.config.ts]
import { defineNuxtAnalyticsConfig } from '@liria24/analytics/nuxt/runtime'

export default defineNuxtAnalyticsConfig({
    getAccessToken: () => getGoogleAccessTokenFromServerSecrets(),
})
```

If a query fails, confirm property spelling, Search Console access for the authorized account,
the OAuth scope, token expiry, and Google API quota errors.

---
title: Cloudflare
description: Use Web Analytics reports and Analytics Engine capabilities.
---

Cloudflare Web Analytics exposes `summary`, `series`, and `breakdown` with metrics
`pageViews`, `visits`, and the current-window `activeUsers`. In Nuxt, configure the built-in
Provider in `nuxt.config.ts`:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
    modules: ['insight-ts/nuxt'],
    insight: {
        providers: {
            cloudflare: { webAnalytics: true },
        },
    },
    runtimeConfig: {
        cloudflare: {
            accountId: '',
            apiToken: '',
            host: 'example.com',
            siteTag: '',
        },
    },
})
```

Set production secrets with `NUXT_CLOUDFLARE_ACCOUNT_ID`, `NUXT_CLOUDFLARE_API_TOKEN`, and
`NUXT_CLOUDFLARE_SITE_TAG`. Plain TypeScript applications can instead compose
`cloudflareWebAnalytics()` with `defineProvider()` directly.

Returned sampling, partial-result, approximation, and freshness metadata is preserved. Missing
calendar dates remain missing points; chart time uses numeric timestamps so the visual gap remains
proportional.

`cloudflareAnalyticsEngine()` can expose a report Source for a dataset, an event destination for a
binding, or both. Analytics Engine remains a provider-native capability rather than a special
“product” domain.

Daily Web Analytics History is declared for `pageViews` and `visits`; `activeUsers` is
non-additive and is not silently rolled up. Configure R2 through Nitro's `storage.insight` mount,
not through Cloudflare SDK or an Insight-specific R2 option.

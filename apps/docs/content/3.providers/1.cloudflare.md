title: Cloudflare
description: Query Web Analytics and use Analytics Engine as an event destination.
---

Analytics SDK provides separate Cloudflare capabilities for aggregate web traffic and custom
events. Configure only the capability you use.

## Web Analytics

You need:

- a Cloudflare account ID;
- a server-side API token that can read Account Analytics;
- the Web Analytics site tag.

```ts
import { createAnalytics } from '@liria24/analytics'
import { cloudflareWebAnalytics } from '@liria24/analytics/cloudflare'

const analytics = createAnalytics({
    name: 'website',
    adapters: [
        cloudflareWebAnalytics({
            accountId: process.env.CLOUDFLARE_ACCOUNT_ID!,
            apiToken: process.env.CLOUDFLARE_API_TOKEN!,
            siteTag: process.env.CLOUDFLARE_SITE_TAG!,
        }),
    ],
})
```

The adapter queries the account-scoped GraphQL dataset and filters it by `siteTag`. It preserves
sampling, approximation, partial-result, and freshness information in report metadata.

Initial archive maintenance can look back up to six months. A monthly partition continues to
refresh through the provider's one-day finalization window, then becomes sealed.

## Analytics Engine

Use an Analytics Engine dataset binding for server-side event writes:

```ts
import { cloudflareAnalyticsEngine } from '@liria24/analytics/cloudflare'

const analyticsEngine = cloudflareAnalyticsEngine({
    binding: env.ANALYTICS,
})
```

For SQL queries, also provide the account ID, an API token with Analytics Engine read permission,
and the dataset name. The current adapter intentionally exposes a narrow event-count dataset
instead of treating a dynamic SQL schema as universally portable.

Initial archive maintenance can look back up to three months. A monthly partition uses a one-day
finalization window.

## Nuxt and Cloudflare bindings

The optional Nuxt integration accepts binding identifiers rather than binding objects:

```ts [nuxt.config.ts]
export default defineNuxtConfig({
    modules: ['@liria24/analytics/nuxt'],
    analytics: {
        name: 'website',
        providers: {
            cloudflare: {
                analyticsEngine: 'ANALYTICS',
                r2: 'ANALYTICS_ARCHIVE',
                webAnalytics: 'your-site-tag',
            },
        },
    },
})
```

Server credentials stay in private runtime config or environment variables. See the [Nuxt
integration](/integrations/nuxt) for archive mounts, event relays, and runtime authorization.

## Troubleshooting

Verify the account ID, API-token permissions, site tag or dataset name, Cloudflare API errors, and
rate-limit responses. Never expose the API token to browser code.

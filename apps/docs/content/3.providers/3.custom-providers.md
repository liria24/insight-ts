---
title: Custom Providers
description: Add application or service Sources without changing Core.
---

Use a custom Provider when your application needs a source that does not belong to a built-in
Provider. A Source owns its input, exact dedupe behavior, output, and metadata.

## Example

```ts
import { createInsight, defineProvider, defineSource } from 'insight-ts'

const logs = defineSource({
    normalize: (query: { cursor?: string }) => ({ cursor: query.cursor ?? '' }),
    key: ({ cursor }) => cursor,
    execute: async ({ cursor }, { signal }) => ({
        data: await loadLogs({ cursor, signal }),
        meta: { nextCursor: cursor || 'page-2' },
    }),
})

const insight = createInsight({
    providers: [defineProvider({ id: 'app', sources: { logs } })],
})

const result = await insight.query((q) => ({ logs: q.source.app.logs({}) }))
```

## Source contract

`normalize()` must be pure and deterministic. `key()` returns the exact semantic dedupe key.
`execute()` receives the normalized query plus a Provider ID, Source ID, and optional `AbortSignal`.
Core creates the result envelope and does not interpret cursors or log entries.

::tip
Use `defineMetricSource()` from `insight-ts/metrics` only when selected Metrics, dimensions,
typed filters, aggregation, and rollup really match your Source. A generic Source is the smaller
contract for logs, funnels, traces, and billing entities.
::

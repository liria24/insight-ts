---
title: Custom Providers
description: Add application or third-party adapters without exposing backend topology.
---

Use a custom Provider when application data should participate in a canonical capability. The
smallest current authoring helper is `defineMetricAdapter()`.

```ts
import { createInsight, defineProvider } from 'insight-ts'
import { defineMetricAdapter } from 'insight-ts/metrics'

const usage = defineMetricAdapter({
    dimensions: { environment: 'string' },
    metrics: {
        requests: { aggregation: { kind: 'sum' }, rollup: 'additive' },
    },
    async execute(query, { signal }) {
        return loadUsage(query, signal)
    },
})

const insight = createInsight({
    providers: [defineProvider({ adapters: { usage }, id: 'app' })],
})

const result = await insight.query((q) => ({
    usage: q.metrics({ metrics: ['requests'], time }),
}))
```

Adapter execution receives only the canonical plan plus Provider, adapter, Scope, and abort
context. Native resources and field names stay inside the Provider implementation.

`normalize()` and exact dedupe are supplied by the canonical helper. Provider validation and
translation still happen before network I/O. Create a generic capability contract only when a real
data model cannot use the shipped Metrics, Logs, or Traces contracts.

The `cloudflare()` Provider can enable Web Analytics, Workers Observability, Analytics Engine, or
any combination. They are separate Cloudflare products with different storage, credentials,
adapters, and constraints; configuring one does not enable or depend on another.

## Web Analytics

### Setup

Web Analytics reads traffic aggregates through Cloudflare's GraphQL API. It needs an account ID,
API token, and site tag. `host` is an optional additional restriction.

```ts
import { createInsight } from 'insight-ts'
import { cloudflare } from 'insight-ts/cloudflare'

const insight = createInsight({
    providers: [
        cloudflare({
            accountId,
            apiToken,
            webAnalytics: { host: 'example.com', siteTag },
        }),
    ],
})
```

### Query

```ts
const { traffic } = await insight.query((q) => ({
    traffic: q.metrics({
        metrics: ['pageViews', 'visits'],
        dimensions: ['path'],
        time: {
            from,
            to,
            grain: 'day',
        },
        where: {
            country: { in: ['JP', 'US'] },
        },
        limit: 20,
    }),
}))
```

Metrics are `pageViews` and `visits`. Dimensions are `time`, `path`, `referer`, `country`,
`device`, `browser`, `host`, and `os`. Non-time dimensions support `eq`, `ne`, `in`, and `notIn`
filters. Query buckets currently use UTC.

Cloudflare may sample adaptive-group data. Insight.ts preserves `sampled`, `sampleRate`, and
`approximate` quality fields. GraphQL errors and the native row cap remain visible as partial-result
warnings rather than being treated as complete data.

::warning
Web Analytics has no native `activeUsers` metric. A recent-activity number based on `visits` is an
application KPI; keep its short range and label explicit.
::

## Workers Observability

Enable `workersObservability` to register canonical Logs, Traces, and Workers Metric adapters over
Cloudflare's finite [Telemetry query API](https://developers.cloudflare.com/api/resources/workers/subresources/observability/subresources/telemetry/methods/query/).
The account token needs Workers Observability access.

```ts
const insight = createInsight({
    providers: [
        cloudflare({
            accountId,
            apiToken,
            workersObservability: true,
        }),
    ],
})
```

`datasets` can narrow queries when the account has several observability datasets. Omit it to use
all available datasets.

### Logs and traces

Consumers use only canonical fields. The adapters translate service, severity, trace ID, span ID,
trace name, status, and duration to Cloudflare `$metadata.*` filters internally.

```ts
const { errors, slowFailures } = await insight.query((q) => ({
    errors: q.logs({
        time,
        where: {
            service: 'api',
            severity: 'error',
        },
        limit: 100,
    }),
    slowFailures: q.traces({
        time,
        where: {
            durationMs: { gte: 500 },
            service: 'api',
            status: 'error',
        },
    }),
}))
```

Workers Logs preserve `$metadata.id` as the canonical stable log ID. Trace summaries preserve
Cloudflare trace IDs, service lists, root names, duration, span count, and errors. Native offsets
stay inside the opaque `meta.pagination.next` cursor. Sampling and ABR facts appear in canonical
Quality, and truncated log events are explicitly partial.

### Workers metrics

Telemetry calculations expose `workerInvocations` and `workerDurationP95`. Both support scalar or
UTC time-series queries; minute, hour, day, and week buckets are supported. The percentile is
non-additive, so History rejects unsafe rollup.

```ts
const { workers } = await insight.query((q) => ({
    workers: q.metrics({
        metrics: ['workerInvocations', 'workerDurationP95'],
        time: {
            from,
            to,
            grain: 'hour',
        },
    }),
}))
```

Workers Observability composes with generic History. A sync drains Cloudflare native continuation
before it marks a Log or Trace range complete. Live Tail remains outside finite `query()` and is
not exposed as a Cloudflare-specific SDK method.

## Analytics Engine

Analytics Engine supports event writes through a Worker binding and aggregate reads through the
Cloudflare SQL API. Either capability can be configured independently.

### Write-only event delivery

Pass the Worker Analytics Engine binding without a dataset. Declare application events on
`createInsight()` and send them through `insight.track()`.

```ts
const insight = createInsight({
    events: {
        signup: {
            properties: {
                plan: ['free', 'pro'],
            },
        },
    },
    providers: [
        cloudflare({
            analyticsEngine: { binding: env.INSIGHT_EVENTS },
        }),
    ],
})

await insight.track('signup', { plan: 'pro' })
```

Each tracked event writes one data point. Its index is `name:<event-name>`; blobs contain the event
name, JSON properties, and origin. The shared event ID and timestamp are not projected into fields
that this layout does not support. The encoded index is limited to 96 bytes and the combined blobs
to 16 KiB; oversized events fail before the binding write.

### Read-only dataset queries

Provide a dataset plus account credentials to register the Analytics Engine Metric adapter. The dataset must
be a valid SQL identifier.

```ts
const insight = createInsight({
    providers: [
        cloudflare({
            accountId,
            apiToken,
            analyticsEngine: { dataset: 'insight_events' },
        }),
    ],
})

const { events } = await insight.query((q) => ({
    events: q.metrics({
        metrics: ['events'],
        dimensions: ['name'],
        time: {
            from,
            to,
            grain: 'day',
        },
        where: {
            name: 'signup',
        },
    }),
}))
```

The only metric is `events`. Queries may be scalar, use `time` for a series, or use `name` for an
event-name breakdown. The current filter surface supports only equality on `name`; time buckets are
UTC. Queries cannot begin before Analytics Engine's three-month retention window.

Analytics Engine's `_sample_interval` is applied to event counts. When sampling occurs, the result
retains `sampled`, `sampleRate`, and `approximate` quality fields.

### Combined read and write

Configure both `dataset` and `binding` to query the dataset and deliver events through one Provider.

```ts
cloudflare({
    accountId,
    apiToken,
    analyticsEngine: {
        binding: env.INSIGHT_EVENTS,
        dataset: 'insight_events',
    },
})
```

Web Analytics can be added to the same `cloudflare()` call with `webAnalytics`, but its data and
quality semantics remain independent from Analytics Engine.

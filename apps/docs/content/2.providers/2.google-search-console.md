Use the Google Search Console Provider for typed Search Analytics Metrics. Your host supplies an
access-token callback; Insight.ts neither stores OAuth credentials nor creates login routes.

## Setup and query

```ts
import { createInsight } from 'insight-ts'
import { googleSearchConsole } from 'insight-ts/google-search-console'

const insight = createInsight({
    providers: [
        googleSearchConsole({
            auth: { getAccessToken },
            property: 'sc-domain:example.com',
        }),
    ],
})

const search = await insight.metrics({
    metrics: ['clicks', 'impressions', 'ctr', 'averagePosition'],
    dimensions: ['query', 'page'],
    time,
    where: {
        page: { contains: '/docs' },
    },
})
```

## Supported API

Metrics are `clicks`, `impressions`, `ctr`, and `averagePosition`. Supported dimensions are date,
hour, query, page, country, device, and search appearance. Adapter typing prevents unsupported
filters, Metrics, and dimension combinations before network I/O.

## Constraints

::caution
Grouped Search Analytics requests return top rows rather than a guaranteed complete set, so any
result containing `rows` is marked partial. Aggregate-only results do not receive that warning.
Incomplete dates, range expansion, execution limits, and Pacific calendar boundaries remain visible
in metadata and Quality.
::

`meta.freshness.provisionalFrom` is the first incomplete Pacific date or hour normalized to an
absolute timestamp. History uses that boundary independently from `quality.partial`, so permanent
top-row partiality can remain stable while only recent incomplete data is refreshed.

Insight.ts handles native pagination internally. Use the canonical query `limit` when the query
itself should return fewer rows.

The query-wide aggregate comes from a dimensionless Search Analytics request. Grouped rows use their
own request, and `both` runs the requests concurrently with one access token. Aggregate CTR is
recomputed from aggregate clicks and impressions; average position preserves Google's native
dimensionless value. Neither metric is inferred from top rows.

## Advanced execution settings

Normal applications should keep the conservative default execution limit. If a measured workload
requires a different hard ceiling, configure it explicitly:

```ts
googleSearchConsole({
    advanced: { maxRows: 500_000 },
    auth: { getAccessToken },
    property: 'sc-domain:example.com',
})
```

Reaching this ceiling marks the result partial and adds an `execution-limit` quality warning. The
advanced setting controls Provider work; it does not change canonical query semantics.

`ctr` is a derived ratio. `averagePosition` is not additive; queries that would require History to
roll it up execute live. Search Console History captures Pacific daily buckets. A History-backed
query must use `timezone: 'America/Los_Angeles'` and Pacific-midnight range boundaries; incompatible
queries execute live.

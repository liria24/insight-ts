---
title: Styling
description: Customize Analytics Vue UI with class, ui slots, data attributes, and semantic CSS variables.
---

Analytics Vue UI follows a small, consistent styling contract inspired by Nuxt UI. It does not
depend on Nuxt UI, Tailwind CSS, or a class-merging runtime.

## Usage

```vue
<AnalyticsStat
    class="rounded-lg border p-4"
    :report="report"
    metric="pageViews"
    :ui="{
        label: 'text-sm text-muted',
        value: 'text-2xl font-semibold',
    }"
/>
```

Import the baseline CSS once in a plain Vue application:

```ts
import '@liria24/analytics/vue/style.css'
```

Nuxt injects it automatically when an Analytics Vue component is detected unless configured
otherwise.

## Styling contract

| Surface     | Meaning                                                             |
| ----------- | ------------------------------------------------------------------- |
| `class`     | Classes applied to the component root                               |
| `ui.root`   | Additional classes applied to the component root                    |
| `ui.<slot>` | Classes applied to the corresponding named style slot               |
| `data-slot` | Stable selector on every styleable element                          |
| `$attrs`    | Forwarded to the root; a caller-provided `data-slot` takes priority |

The SDK passes class values directly to Vue's class binding. It does not parse utilities, resolve
variants, or merge conflicting classes.

> Tailwind is supported as a consumer styling choice, not as an Analytics SDK dependency.

The same API works with UnoCSS, plain CSS classes, CSS Modules, and other utility frameworks.

## Class values

`class` and every `ui` key accept `AnalyticsUIClass`:

```ts
type AnalyticsUIClass =
    string | readonly AnalyticsUIClass[] | Readonly<Record<string, boolean | undefined>>
```

That means normal Vue class arrays and conditional class objects work without a transform layer.

## Slots

Named Vue slots receive the resolved `ui` object in addition to their existing data props:

```vue
<AnalyticsStat :report="report" metric="pageViews">
    <template #value="{ formatted, ui }">
        <strong :class="ui.value">
            {{ formatted }}
        </strong>
    </template>
</AnalyticsStat>
```

Using a slot replaces that element's default markup. Apply `ui.<slot>` to custom markup when the
same styling should be preserved.

## Semantic CSS variables

SVG axis and grid elements cannot receive Vue classes directly. The chart uses semantic variables
instead:

| Variable                       | Purpose                        |
| ------------------------------ | ------------------------------ |
| `--analytics-text`             | Default component text         |
| `--analytics-text-muted`       | Secondary text                 |
| `--analytics-text-highlighted` | Titles and emphasized values   |
| `--analytics-border`           | Borders and separators         |
| `--analytics-background`       | Tooltip and surface background |
| `--analytics-chart-axis`       | Axis labels                    |
| `--analytics-chart-grid`       | Chart grid lines               |

Defaults fall back to matching Nuxt UI semantic variables when they exist, then to neutral CSS
colors. Override them on any ancestor:

```css
.analytics-panel {
    --analytics-chart-axis: #52525b;
    --analytics-chart-grid: #d4d4d8;
}
```

## API

Every component exports a component-specific `*UI` interface. See each component page for the
complete list of keys. No renderer theme or utility-framework type is part of the public API.

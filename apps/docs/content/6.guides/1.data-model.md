title: Data model
description: Read generic Source results, Metric data, quality, and Source metadata correctly.
---

Use this guide when deciding where a result belongs in application code. Every Source returns its
own `data` and `meta`; Core adds only the common envelope.

## Result shape

```ts
interface QueryResult<TData, TMeta extends object = {}> {
    data: TData
    meta: TMeta & {
        quality?: QueryQuality
        queriedAt: string
        source: string
    }
}
```

## Metric results

A Metric Source returns selected Metrics as `{ value: number | null, points? }`. Definitions carry
semantic units, structured aggregation, and rollup. UI code owns currency, percentage, compact
notation, locale, and fraction digits.

## Read metadata at its level

- `meta.quality` expresses approximation, partiality, sampling, thresholding, and warnings.
- Source metadata expresses cursor, freshness, temporal fields, or Provider-native details.
- History Fidelity is range-scoped Source metadata and is distinct from Provider Quality.

::tip
Render quality close to the value it qualifies. Do not turn a sampling warning into a zero, a
missing value, or an apparently exact aggregate.
::

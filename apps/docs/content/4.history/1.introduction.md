---
title: History
description: Preserve canonical Metrics, Logs, and Traces beyond Provider retention.
---

Use History when native Provider retention is shorter than the range your product needs. Supported
canonical capabilities use the same query methods whether data comes from storage or a live
Provider. Missing or provisional intervals are synchronized before the result is returned.

```ts
import { createHistory } from 'insight-ts/history'

const insight = createInsight({
    providers,
    history: createHistory({
        repository,
        capabilities: ['metrics', 'logs', 'traces'],
        // Optional when all configured Scopes should be preserved.
        scopes: ['production'],
    }),
})

await insight.history.sync({
    range: { from: '2026-01-01T00:00:00.000Z', to: '2026-09-01T00:00:00.000Z' },
})
```

Omit `capabilities` and `scopes` to enable every History-capable capability in every configured
Scope. `sync()` accepts the same optional selection to narrow one run.

## Exact query behavior

History serves stored data only when it can reproduce the whole query exactly. Otherwise, the
whole query executes live.

Metric History must satisfy every requested `aggregate` and `rows` projection. Stored data never
answers a query at a finer grain, and bucket timezones must be compatible. Safe additive UTC data
may roll up to a coarser grain, and ratios are recomputed from their inputs. Non-UTC rows currently
require their captured grain. Unsafe non-additive reconstruction falls back to a live query.

Stored Logs and Traces retain stable IDs and ordering. Pageable results continue with
`insight.next(result)` just like live results.

## Coverage and lifecycle

A completed empty interval means synchronization found no matching data. Provider `QueryQuality` is
preserved independently from refreshability: a stable partial result remains covered, while
`meta.freshness.provisionalFrom` keeps only the changing suffix refreshable.

Use `insight.history.expire({ before })` to delete aged ranges explicitly.

::caution
History is not a persistent query-result cache. A repository may compress data losslessly, but it
must preserve the exact canonical values needed by supported queries.
::
